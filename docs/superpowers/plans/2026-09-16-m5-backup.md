# M5 导出 / 导入备份 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让用户能把全部训练记录导出成一个文件保存到别处，并且能导回来。

**为什么这条最紧急**：数据现在只存在一台手机的本地 SQLite 里。手机丢了、App 卸载了、系统清理了，**训练记录全部消失且无法恢复**。这是目前这个 App 唯一「会永久损失用户资产」的缺口。

**Architecture:** 分三层 —— 纯逻辑（备份格式的构造与校验，可完整单测）→ 仓储层（读写四张表，用事务保证原子性）→ 文件层与界面（`expo-file-system` / `expo-sharing` / `expo-document-picker`）。**校验必须先于任何写入**，校验不过就整份拒绝。

**Tech Stack:** Expo SDK 57 / TypeScript / expo-sqlite（生产）/ node:sqlite（测试）/ expo-file-system / expo-sharing / expo-document-picker

## Global Constraints

沿用前两份计划（`2026-09-15-gym-tracker-m1-m2.md`、`2026-09-16-m3-history.md`）的 `## Global Constraints`，要点：

- **分层硬规则**：`app/` 与 `src/components/` 不直接 import `src/db/`、不写 SQL；数据访问只经 `src/repositories/`。
- **jest 必须带 `--runInBand --no-cache`**：前者绕沙箱 `spawn EPERM`，后者防**假绿**（实测 jest 缓存会在文件改动后不失效）。
- **读中文文件用 read 工具**，不要用 `Get-Content`（显示乱码是假象）。
- **`.ps1` 里注释只能用 ASCII** —— 实测紧跟中文注释的那一行会被 PowerShell 静默跳过。
- **`SqlExecutor.run()` 多语句必须走 exec 语义**（`prepare()` 只执行第一条，静默丢表）。
- **所有 `ORDER BY started_at DESC` 要带 `rowid DESC` 兜底**。
- **动态路由导航用对象形式**（SDK 57 的 `typedRoutes` 不生成模板字符串类型）。
- **隐藏导航栏的页面自己用 `useSafeAreaInsets()`**。
- **RN 0.86.3 没有 `StyleSheet.absoluteFillObject`**，只有 `absoluteFill`。
- **不要写会随机变红的测试** —— 时间相关断言必须显式固定时间戳，不要依赖"两次调用恰好落在同一毫秒"。
- 所有面向用户的文案是简体中文。
- **v1 只导 kg**，不做单位换算。

## 备份文件格式（本计划的唯一权威定义）

```jsonc
{
  "format": "gym-tracker-backup",     // 固定字符串，用来识别"这是不是我们的文件"
  "version": 1,                        // 备份格式版本。读到比当前大的版本必须拒绝
  "schemaVersion": 1,                  // 导出时的数据库 schema 版本，仅供参考
  "exportedAt": 1789560000000,         // 导出时刻的毫秒时间戳
  "data": {
    "exercises": [ /* Exercise 行，字段与 domain/types.ts 一致 */ ],
    "sessions": [ /* WorkoutSession 行 */ ],
    "sessionExercises": [ /* SessionExercise 行 */ ],
    "sets": [ /* SetEntry 行 */ ]
  }
}
```

**导入语义：整体替换。** 不是合并 —— 合并要处理 id 冲突与"同一场训练导两遍"的去重，复杂度高且容易悄悄产出重复记录。替换是"从备份恢复"的标准语义，代价是必须先弹确认框告诉用户会替换掉多少东西。

### Task 1: 备份格式的构造与校验（纯逻辑，TDD）

**Files:**
- Create: `src/domain/backup.ts`
- Test: `src/domain/backup.test.ts`

**Interfaces:**
- Consumes: `Exercise`、`WorkoutSession`、`SessionExercise`、`SetEntry`（`src/domain/types.ts`）
- Produces:
  - `const BACKUP_FORMAT = 'gym-tracker-backup'`
  - `const BACKUP_VERSION = 1`
  - `interface BackupData { exercises: Exercise[]; sessions: WorkoutSession[]; sessionExercises: SessionExercise[]; sets: SetEntry[] }`
  - `interface BackupFile { format: string; version: number; schemaVersion: number; exportedAt: number; data: BackupData }`
  - `buildBackup(data: BackupData, schemaVersion: number, exportedAt: number): BackupFile`
  - `type BackupValidation = { ok: true; backup: BackupFile } | { ok: false; reason: string }`
  - `validateBackup(input: unknown): BackupValidation`

**校验必须覆盖（每一条都要有测试）**：

1. 不是对象 / 是 null / 是数组 → 拒绝
2. `format` 不是 `'gym-tracker-backup'` → 拒绝（**这是识别"用户选错文件"的关键**）
3. `version` 不是正整数 → 拒绝
4. `version > BACKUP_VERSION` → 拒绝，理由里要说明"文件来自更新的版本"（**不能静默降级读取**）
5. `data` 不是对象 → 拒绝
6. 四个数组缺任何一个 / 不是数组 → 拒绝
7. **每条记录的形状与字段类型**：`SetEntry.weight` 必须是有限数字、`reps` 必须是整数、`isCompleted` 必须是布尔、`restSeconds` 必须是 `number | null`……任一不符 → 拒绝，理由里带上"第几条记录的哪个字段"
8. **引用完整性**（这条最容易漏，但漏了就会导入出一堆孤儿数据）：
   - 每个 `sessionExercise.sessionId` 必须能在 `sessions` 里找到
   - 每个 `sessionExercise.exerciseId` 必须能在 `exercises` 里找到
   - 每个 `set.sessionExerciseId` 必须能在 `sessionExercises` 里找到
   - 违背 → 拒绝，理由要指出是哪条
9. 合法输入 → `ok: true`，且 `backup` 里的对象是**规范化过的**（不要直接把 `input` 里多出来的字段透传下去）

**关键要求**：`validateBackup` **只读不写**，绝对不能碰数据库。它的失败必须表现为返回 `{ ok: false, reason }`，而不是抛异常。

### Task 2: 仓储层的导出与导入（事务）

**Files:**
- Create: `src/repositories/backupRepo.ts`
- Test: `src/repositories/backupRepo.test.ts`

**Interfaces:**
- Consumes: `SqlExecutor`、`SCHEMA_VERSION`（`src/db/types.ts`）、Task 1 的 `BackupData` / `BackupFile` / `buildBackup`
- Produces:
  - `exportAll(exec: SqlExecutor): Promise<BackupFile>`
  - `importAll(exec: SqlExecutor, backup: BackupFile): Promise<void>`

**导出**：把四张表全部读出来，字段名映射回 `domain/types.ts` 的驼峰命名（**复用各仓储里已有的行映射逻辑，不要重写一遍** —— 若要提取，提到 `src/repositories/mappers.ts`，并让原仓储也用它，避免两份映射漂移）。

**导入必须在一个事务里完成**，顺序：
1. `DELETE FROM set_entry`
2. `DELETE FROM session_exercise`
3. `DELETE FROM session`
4. `DELETE FROM exercise`（**动作库也会被替换掉** —— 备份文件里带着它，这样换设备后自定义动作不会丢）
5. 按 `exercises → sessions → sessionExercises → sets` 的顺序插入

**关于事务**：`SqlExecutor` 目前没有事务抽象。**在 `backupRepo` 内部用 `exec.run('BEGIN')` / `COMMIT` / `ROLLBACK` 手写**即可，但要：
- 出错时 `ROLLBACK`，并把原始异常抛出去
- 测试要覆盖"中途失败会回滚，库里数据不变"—— 构造一份**引用了不存在 id 的 set** 来触发外键失败

- [ ] **Step 1: 写失败的测试**（至少 8 条）

必须有：
- 导出空库 → 四个数组都是空的，`format` / `version` / `schemaVersion` 正确
- 导出有数据的库 → 各表条数与内容正确，字段是驼峰
- **导出 → 导入到另一个空库 → 两边内容完全一致**（往返一致性，最关键的一条）
- 导入会**整体替换**：目标库原有的数据全部消失，只剩备份里的
- 导入后**自增/顺序字段正确**（`position` 保持原样）
- **中途失败会回滚**：喂一份 `sets` 引用了不存在 `sessionExerciseId` 的备份，`importAll` 应抛错，且**目标库的数据与调用前完全一致**
- 导入一份合法的空备份 → 库被清空（这是合法行为，不是错误）
- 导入后 `listSessionSummaries` 能正确算出容量（端到端串一下）

### Task 3: 文件读写与设置页入口

> ⚠️ **这一步依赖真机**：`expo-file-system` / `expo-sharing` / `expo-document-picker` 在 Node 下都跑不了，**没有任何单测能覆盖它**。写完后必须由主 agent 用 adb 在真机上验证（导出 → 分享面板出现；选文件 → 能选中导出的那份）。

**Files:**
- Create: `src/lib/backupFile.ts`
- Modify: `app/(tabs)/settings.tsx`
- Modify: `package.json`（新增三个 expo 依赖）

**Interfaces:**
- Produces: `shareBackup(exec): Promise<void>`、`pickAndImportBackup(exec): Promise<{ ok: boolean; message: string }>`

**依赖**：`npx expo install expo-file-system expo-sharing expo-document-picker`（如果沙箱下 `expo install` 不可用，就手动 `npm install` 对应版本，并在报告里说明）。

**导出流程**：`exportAll` → `JSON.stringify(backup, null, 2)` → 写到 `FileSystem.cacheDirectory` 下一个带日期的文件名（如 `gym-backup-2026-09-16.json`）→ `Sharing.shareAsync(fileUri, { mimeType: 'application/json' })`，让用户自己发到微信/邮件/网盘。

**导入流程**：`DocumentPicker.getDocumentAsync({ type: 'application/json' })` → 读文件内容 → `JSON.parse`（**parse 失败要给出"这不是一个有效的 JSON 文件"，不要让异常冒到界面**）→ `validateBackup` → 校验不过 → 弹 `Alert` 说明原因并**直接返回，一个字节都不写库** → 校验通过 → 弹**二次确认**（写明："将用备份里的 N 场训练替换当前的 M 场训练，此操作不可撤销"）→ 确认后 `importAll` → 成功后提示并刷新。

**设置页**：在现有「组间休息的一般参考」卡片**上方**加一张「备份」卡片，两个按钮：**导出备份**、**导入备份**。导入按钮要用警示色（这是会覆盖数据的操作）。运行中禁用按钮并显示进行中文案，防止连点两次。
